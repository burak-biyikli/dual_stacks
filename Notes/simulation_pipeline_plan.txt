Phased gem5 simulation pipeline
===============================

Phase 0: Record the plan
------------------------
Keep the work scoped to the benchmark configurations and
scripts/05_run_simulations.py. Existing microbenchmark configurations remain
unchanged.

Phase 1: Dry-run driver and mock config
---------------------------------------
Create a copy of run_o3_mr.py that accepts benchmark sweep arguments and keeps
the minimal topology. The driver resolves profiles and run matrices without
building or running gem5, and writes a manifest.

Phase 2: Mock simulations
-------------------------
Build gem5 once, run GAPBS directly and PARSEC through parsecmgmt -s, and save
per-run logs, stats, metadata, and failure status.

Phase 3: Trace-derived sweeps
-----------------------------
Use integer PRF values plus histogram-derived reductions, load/store port
pairs, and per-trace LQ/SQ scaling based on provably-private stack traffic.

Phase 4: Skylake-like benchmark config
--------------------------------------
Move to a shared benchmark system with a Skylake-like O3 core and classic
L1/L2/LLC hierarchy. Support stock, static-only MR, full MR, and trace-sized
LSU modes through configuration arguments.

Phase 5: Best-effort multicore config
-------------------------------------
Add a separate, prominently unvalidated multicore entrypoint that shares the
same construction helpers and command-line contract as the single-core config.

Files added or changed
----------------------
- scripts/05_run_simulations.py
  JSON-driven parameter matrix runner. Supports --experiment-file, --profile-dir,
  --sizes, --benchmarks, --timeout, --grace-period, --jobs, --mem-per-job,
  --skip-build, --dry-run, --output-dir, and --resume.
- scripts/06_extract_data.py
  Post-processing stats extractor. Generates consolidated CSVs and computes config
  aggregates and speedup summaries relative to the stock baseline configuration.
  Supports backward-compatible header and value extraction on older manifests.
- configs/run_o3_benchmark_mock.py
  Minimal topology config that accepts all benchmark arguments but prints and
  ignores the sweep knobs. Use this first for driver/config contract checks.
- configs/benchmark_system.py
  Shared Skylake-like SE builder and argument parser.
- configs/run_o3_benchmark_single.py
  Supported single-core entrypoint using the shared builder.
- configs/run_o3_benchmark_multicore.py
  Explicitly unvalidated multicore construction entrypoint. It is only a
  construction smoke-test aid; do not use its results for conclusions.

Implemented experiment matrix
-----------------------------
- Stock integer-PRF runs: explicit values plus base 180 and accepted
  histogram-derived values. Default: 100,150,200,10%,15%.
- Stock LSU bandwidth runs: 1:1 and 3:2 load:store ports. The default 2:1
  baseline is represented by the stock PRF baseline and is intentionally not
  duplicated.
- MR static-only baseline, MR full (static plus dynamic) baseline, and MR
   static-only with trace-derived LQ/SQ sizing.
- Trace-derived LQ/SQ uses the overall provably-private fraction because the
   profiler does not record privacy split separately for pushes and pops.

Manifest and result behavior
---------------------------
- Each planned run records profile provenance/status, resolved parameters,
  command, outdir, cwd, and final status in JSON and CSV manifests.
- Results default to results/gem5_sim_runs/<timestamp>/.
- Paths recorded in manifests are relative (outdir is relative to output dir,
  profile_path is relative to project root) making results directories fully portable.
- Timed-out trace profiles with nonzero memory counters and a histogram remain
  eligible, and their profile status is retained in the manifest.
- --dry-run writes only the manifest; it never patches, builds, or runs gem5.
- --skip-build reuses an existing build/X86/gem5.opt for short validation runs;
  normal study runs still apply patches and build once.
- Real runs apply patches, build gem5 once, then continue after individual run
  failures and return nonzero at the end if any failed.
- --resume caches/skips runs that have existing, non-empty stats.txt files (even if
  they timed out), re-runs failed ones, and defaults to the latest simulation run
  directory.
